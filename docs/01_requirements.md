# 01_requirements.md（要件定義書）

対象バージョン: v1.1.3

## 1. 概要

Multi Grep Replacer は、複数フォルダ内のファイルに対して、複数の検索・置換ルールを一括で実行するデスクトップアプリです。Python（Tkinter）版のUI応答性の問題を解消するため、Electronで作り直しました。

| 項目 | 内容 |
|---|---|
| 対応OS | macOS 10.14以降（universal）、Windows 10以降（x64） |
| 想定ユーザー | Web制作者・開発者・文書の一括修正を行う人 |
| 技術スタック | Electron 25 + Vanilla JS（フレームワークなし） |

## 2. 機能要件

### 2.1 対象ファイルの指定
- 対象フォルダを複数指定できる（Browse / パス入力）
- サブフォルダを再帰的に検索する
- 拡張子をカンマ区切りで絞り込める。空欄なら全ファイルが対象
- `node_modules/**`、`.git/**`、`dist/**`、`build/**` は対象外
- 100MBを超えるファイルは対象外

### 2.2 検索・置換ルール
- ルールを複数登録し、上から順に適用する
- ルールごとに有効・無効を切り替えられる
- 一致はリテラル文字列で、正規表現は使えない
- 大文字小文字は区別する
- From/To を `trim()` しない。前後のスペースも検索・置換の対象
- To が空文字なら一致箇所を削除する。ルールの有効判定は From のみで行う

### 2.3 置換タブ
- 実行前に確認ダイアログを表示する
- 実行中は進捗モーダルを表示する
- Pause で一時停止、Resume で再開できる。処理中のファイルは完了させ、次の区切りで止まる
- Stop で実行を止められる。処理済みの変更は残り、結果は部分結果として表示する。リネームが未実行なら行わない
- 実行に失敗したらエラーを表示する。結果を偽装しない
- 実行後は結果モーダルに、ファイル・ルール別の件数を表示する
- 結果は選択コピー、Copy Summary、CSV出力ができる

### 2.4 検索タブ（Grep）
- ファイルを変更せず内容を検索する。ルールの From が検索語で、複数語はOR検索
- 結果は `パス:行:列: 前後の文字列` の形式で、一致箇所をハイライトする
- 長い行は一致箇所の周辺だけを表示する（既定120文字）
- バイナリファイルは内容検索の対象外。上限は10,000件
- 結果は選択コピー、Copy、CSV出力ができる

### 2.5 対象オプション（v1.1.0）
タブ直下のチェックボックスで指定する。検索・置換の両方に効き、既定はすべてオフ。

| オプション | 対象 | 例 |
|---|---|---|
| ファイル名を対象に含める | 拡張子を除いた部分 | `foo.html` の `foo` |
| 拡張子を対象に含める | ドットを含む拡張子 | `foo.html` の `.html` |
| 両方オン | ファイル名全体 | `ly-single4efA.css` → `ly-single4vnA.css` |
| `\n\t` を有効にする | From/To の `\n` `\t` `\r` `\\` を解釈 | `\n` が改行に一致 |

- 拡張子は最後の1つだけ（`a.tar.gz` なら `.gz`）。`.gitignore` のようなドットファイルは全体をファイル名として扱う
- 未知のエスケープ（`\d` など）はそのまま残す
- フォルダ名は変更しない

リネームの安全要件:
- 内容の置換が完了してから、1件ずつリネームする
- 既存ファイルを上書きしない。衝突したファイルはリネームせず、結果に ❌ で表示して処理を続ける
- 空の名前、`.`、`..`、パス区切り、制御文字を含む名前は拒否する
- ファイル名が消えて隠しファイルになる変更は拒否する
- 内容の読み書きに失敗したファイルはリネームしない

### 2.6 設定管理
- ルール・フォルダ・拡張子・対象オプションをJSONで保存、読み込みできる
- 対象オプションが未指定の設定を読み込むと、オフに戻す
- 組み込みテンプレートと最近使った設定を選べる

### 2.7 CSV出力
- RFC4180に沿ってエスケープする
- 先頭が `=` `+` `-` `@` タブ・CR のセルには `'` を付け、表計算ソフトで数式として評価されないようにする

### 2.8 その他のUI
- テーマ切り替え（ライト / ダーク / OS連動）
- キーボードショートカット（Cmd/Ctrl + S / O / E / N / F）

## 3. 非機能要件

| 分類 | 要件 |
|---|---|
| UI応答性 | ボタン操作の反応は100ms以内 |
| 処理性能 | 1,000ファイルを30秒以内で処理 |
| メモリ | 200MB以下 |
| セキュリティ | `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。IPCは preload 経由で、自分のページからのみ受け付ける。外部ページへの遷移と新しいウィンドウは拒否する |
| データ保護 | 置換は元に戻せないため、実行前に確認する。リネームは上書きしない |
| 起動 | 2回目の起動は既存ウィンドウを前面に出す（シングルインスタンス） |

## 4. 既知の制約

- **バックアップなし:** 置換前の自動バックアップ機能はない
- **停止の粒度:** Stop と Pause はバッチ（最大10ファイル）の区切りか、リネーム1件の区切りで効く。処理中のファイルは中断しない
- **大容量ファイル:** 置換はファイル全体をメモリに読み込む。ストリーム処理は `performance-optimizer.js` にあるが、置換の実行経路では使っていない
- **文字コード:** UTF-8のみ
- **プレビュー:** 置換内容の事前プレビューはUIにない
- **リネームの連鎖:** `a→b`、`b→c` のように順に空く名前は、処理順によって衝突扱いになることがある
- **署名:** macOS版は未署名。初回起動時に右クリックから開く必要がある
- **対象フォルダの範囲:** パスの直接入力に対応するため、置換の対象フォルダは制限していない。レンダラーでスクリプトが動いた場合、任意のフォルダを置換できる
